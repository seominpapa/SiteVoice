# SiteVoice

다른 앱에서 단축키를 눌러 말을 받아쓰고, 번복과 반복, 군더더기만 정리해 원래 입력 칸에 붙여넣는 한국어 데스크톱 앱입니다. 정리가 끝나면 원문과 정리 결과를 따로 볼 수 있습니다. 번역이나 내용 축약은 하지 않습니다.

## 시작하기

1. **시작하기**에서 개인 OpenAI API 키를 저장하고 **키 확인**을 누릅니다. 키 확인은 설정된 두 모델의 정보 조회만 실행합니다. 계정의 모델 실행 권한과 잔액은 실제 요청 시 별도로 적용됩니다.
2. **마이크 권한**에서 입력 장치를 허용하고, 테스트 버튼으로 입력 신호를 확인합니다. macOS는 **시스템 설정 → 개인정보 보호 및 보안 → 마이크**에서 SiteVoice을 허용해야 합니다.
3. macOS의 자동 입력은 **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 SiteVoice을 허용해야 합니다. 앱의 **권한 확인 · 설정 열기**로 요청할 수 있습니다. 거부 후 권한을 변경하면 앱을 완전히 종료하고 다시 시작해 보세요. 개발용 Electron과 패키징된 SiteVoice의 권한은 다를 수 있습니다.
4. 외부 앱의 텍스트 입력 칸에 커서만 둔 뒤 **Mac 왼쪽 Fn(🌐) / Windows 로고 키**를 단독으로 짧게 눌렀다 떼어 녹음합니다. 같은 키를 한 번 더 눌렀다 떼면 녹음이 끝납니다. 표시창에서 종료하거나 취소할 수도 있습니다. 작업 중에만 등록하는 **Esc**가 충돌하면 표시창의 취소 버튼을 사용하세요.
5. 원래 입력 칸을 확인할 수 없거나 의미 변경이 의심되면 **결과**에서 직접 복사합니다. 앱이 “붙여넣기 키를 보냈습니다”라고 표시하면, 실제로 문장이 들어갔는지 입력 칸에서 확인하세요.

처음 사용하는 앱은 TextEdit 또는 메모장의 빈 문서로 확인하세요. 암호 입력 칸, 범위가 선택된 입력 칸, 조회가 제한된 편집기, Windows에서 관리자 권한으로 실행된 앱은 자동 입력이 제한될 수 있습니다. 자동으로 Enter나 전송을 누르지 않습니다.

**환경 설정 → 모델과 단축키 → 단축키 입력**에서 원하는 키나 조합을 직접 누르고 **환경 설정 저장**으로 적용합니다. Esc로 입력을 취소하고, **기본값 사용**으로 되돌릴 수 있습니다. 기존 버전에서 지정한 다른 단축키는 유지됩니다.

Mac에서 Fn만 사용하려면 **입력 모니터링 권한 요청**을 누르고, **시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링**에서 허용하세요. Fn(🌐)을 눌렀을 때 이모지나 입력 소스 전환이 같이 열리면 **시스템 설정 → 키보드**에서 🌐 키의 단독 동작을 **아무 동작도 안 함**으로 바꾸거나 다른 단축키를 지정하세요. Windows에서 로고 키 단독 탭은 SiteVoice가 사용합니다. Win+E 등 기존 조합은 그대로 쓰며, 시작 메뉴는 작업 표시줄이나 Ctrl+Esc로 열 수 있습니다.

**환경 설정**에서 녹음 관련 옵션도 바꿀 수 있습니다. 이곳에서 마이크, 전사 모델(`gpt-transcribe`), 정리 모델(`gpt-6-luna`), 용어 사전을 관리할 수 있습니다. 예를 들어 `SiteCAD`, `흙막이`, `숏크리트`를 각각 추가하고 **환경 설정 저장**을 누르세요. 등록 용어는 전사 힌트이며 고정 치환 규칙이 아닙니다.

**화면 테마**에서 밝게 또는 어둡게를 선택할 수 있습니다. 선택은 즉시 적용되며 다음 실행에도 유지됩니다.

창을 닫으면 메뉴 막대/트레이에 남습니다. **완전히 종료**를 누르면 결과가 사라지고 녹음이 중단됩니다. 자동 시작은 켜지지 않습니다.

## 저장과 전달

API 키는 Main에서만 읽으며 Electron의 비동기 `safeStorage`로 암호화합니다. macOS/Windows의 보호 기능이 없으면 키 저장을 거부합니다. 설정 파일에는 모델, 단축키, 마이크 ID, 용어 사전만 남습니다. 음성과 결과는 파일에 기록하지 않습니다. 음성과 텍스트는 전사·문장 정리를 위해 OpenAI에 전송됩니다. 별도 서버, 로그인, 텔레메트리는 없습니다.

숫자·단위·부정 표현의 눈에 띄는 변경은 자동 입력을 보류합니다. 이 검사는 제한된 안전장치이며, 모든 이름·조건·의미 변화를 찾아내지는 못합니다. 정확한 수치가 중요한 문장은 원문과 함께 검토하세요.

## 개발 및 패키징

Node.js 24.13 이상 및 npm이 필요합니다. macOS에서는 Xcode Command Line Tools의 Swift 컴파일러를, Windows에서는 Visual Studio Build Tools의 **Desktop development with C++**와 Windows SDK를 준비하고 **x64 Native Tools Command Prompt**에서 실행하세요.

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run test:coverage
npm run test:e2e
```

Electron E2E는 실행 중인 데스크톱 세션을 사용합니다. 임시 프로필, 가상 마이크, 모의 API만 사용합니다. 유효한 API 키나 실제 녹음은 필요하지 않습니다.

| 명령 | 환경 | 결과 |
| --- | --- | --- |
| `npm run package:mac` | macOS 13+ | Apple Silicon `.app`, `.dmg` |
| `npm run package:mac:intel` | macOS 14+ 대상 | Intel `.app`, `.dmg` |
| `npm run package:win` | Windows x64 + MSVC | NSIS `.exe` |

산출물은 `release/`에 생성됩니다. macOS 개발 빌드는 로컬 서명(ad hoc)만 적용하며 Apple 공증을 하지 않습니다. 배포용은 Developer ID와 공증 설정을 갖추고 `VOICEINPUT_SIGNING=1`로 빌드하세요. 패키징은 원격 게시를 실행하지 않습니다.

## 업데이트

**환경 설정 → 앱 업데이트**에서 시작 시 자동 확인을 켜거나 끌 수 있습니다. 자동 확인을 켜면 다음 실행 때 새 버전을 확인합니다. 새 버전이 있을 때만 설치 여부를 묻고, **업데이트 설치**를 선택한 경우 내려받아 적용합니다.

현재 앱 내 업데이트는 macOS 배포용 빌드에서 지원합니다. 업데이트 배포를 하려면 Developer ID로 서명한 설치본에 신뢰할 수 있는 HTTPS 피드 주소(`VOICEINPUT_UPDATE_URL`)를 넣어 빌드하고, 빌드가 생성한 업데이트 메타데이터와 설치 파일을 해당 피드에 함께 올려야 합니다. 일반 로컬 개발 빌드는 피드에 연결하지 않습니다. 비공개 GitHub 소스 저장소를 만든 것만으로 자동 업데이트가 시작되지는 않습니다.

## 확인 범위

- 단위 및 통합 테스트는 모의 API 요청, 상태 전이, 취소 후 늦은 응답, 전사 원문 보존, API 키 저장, IPC, 오디오 수집을 확인합니다.
- Electron 자동화는 macOS에서 테스트 키가 앱 재시작 뒤에도 읽히는지와 가상 녹음부터 결과까지를 확인합니다. 이 테스트는 실제 마이크·접근성·외부 앱 붙여넣기 검증을 대신하지 않습니다.
- 실기기 검증은 Mac의 TextEdit, Windows의 메모장에서 각각 시행합니다. (1) 권한 허용 후 마이크와 전역 키로 녹음하고 커서 위치에 결과가 들어가는지, (2) 처리 중 다른 입력 칸으로 이동하거나 영역을 선택하면 복사로 전환되는지, (3) 작업 취소/마이크 분리/절전 후 뒤늦게 붙여넣지 않는지, (4) 클립보드 내용을 그대로 보존하는지, (5) 창 닫기/트레이 완전 종료/재실행을 확인합니다. Windows는 NSIS 설치 및 제거도 확인합니다.

구성: `src/main/`은 OS·키·IPC 관리, `src/core/`는 전사와 정리, `src/renderer/`는 한국어 화면과 녹음, `native/`는 macOS AX/Quartz 및 Windows UI Automation/SendInput 보조 프로그램입니다. 디자인은 제공된 DJI 분석 자료의 흰색·회색 표면, 얇은 구분선, 파란색 버튼을 참고했습니다. 밝은 테마와 차콜 배경의 어두운 테마를 제공합니다.
